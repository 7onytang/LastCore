## 产品目标

让设备所有者安装客户端、显式加入一个 LastCore Controller，并查看设备资源与任务状态。Controller 为设备分配一个模型层区间；客户端在本地资源和用户策略允许时接单，加载指定模型片段，参与一次推理并回报结果或失败原因。

客户端是受控的计算节点，不是通用远程命令执行器。首版只执行代码中内置、按版本管理的推理任务类型；任务请求不得携带 shell 命令、任意脚本或可执行文件。

## 首版范围与成功标准

### Must have

- macOS 与 Windows 节点能注册、保存节点凭据、发心跳、获取 assignment、执行允许的任务类型并上报状态。
- 节点可暂停接单、查看当前任务、主动停止客户端；客户端重启后可用已保存身份恢复，不重复注册出新节点。
- 同一 assignment 至多启动一个本地执行实例；重复拉取和重复状态回报可安全处理。
- 客户端在任务取消、失败、超时、Controller 不可达或进程退出时能停止执行并释放本地资源。
- 用户能明确看到 Controller 地址、节点身份、在线状态、接单开关、当前任务和最近错误；配置与日志中不输出 token。
- 在两台桌面设备的受控网络中，完成“注册 → 分配 → 两段推理 → 汇总输出 → 上报完成”的端到端演示，并保留可复现步骤。

### Android 首版边界

- Android 先完成注册、状态展示、接单开关和小型受限任务的前台执行验证。
- 长任务使用用户可见的前台服务并提供停止入口；应用退到后台、设备省电策略、热状态和厂商限制需要真机验证。
- 未完成真机持续运行与功耗验证前，不承诺 Android 能作为稳定的长时推理节点。

### 暂不纳入首版

- 任意远程代码、容器或 shell 执行；无审核模型的自动下载与加载。
- 公网任意节点直连、NAT 穿透、自动端口映射和未知对端发现。
- 节点失联后的任务迁移、断点续算、跨任务抢占和多任务并发。
- 可靠的恶意节点防护、结果密码学验证、计费、积分或贡献排行。
- 未经确认的模型清单、量化格式、推理框架、硬件加速后端和性能目标。

## 用户流程

1. 用户安装客户端，填写 Controller HTTPS 地址和注册凭据。
2. 客户端展示将上报的设备信息；用户确认后注册，凭据保存在系统安全存储中。
3. 客户端开始心跳。用户可以暂停接单，但已运行任务按明确的“继续当前任务”或“停止并报告”策略处理。
4. Controller 下发 assignment。客户端校验任务状态、deadline、任务类型、模型版本、资源预算和上游/下游信息。
5. 客户端加载允许的模型层，参与推理，定期确认 assignment 仍有效，并发送 running、completed 或 failed 状态。
6. 用户查看任务结果摘要和本机错误日志；敏感输入和模型数据不默认写入日志。

## 任务与客户端状态

客户端节点状态：`unconfigured`、`connecting`、`online_accepting`、`online_paused`、`busy`、`offline`、`error`。

单个 assignment 的本地状态：`received` → `validated` → `preparing` → `running` → `completed`；终止路径为 `cancelled`、`failed`、`expired`。终态不可回到活动态；重新执行必须由 Controller 创建新的 assignment ID。

每次状态变化记录 assignment ID、时间、状态和脱敏错误码。重启恢复时先向 Controller 核实任务是否仍活动，再决定恢复或停止；首版若执行器不支持安全恢复，则将本地残留任务标记为需清理并释放资源，不从中间状态盲目续算。

## 工程边界建议

### 当前实现基线

Controller API 契约见 [`API_CONTRACT.md`](API_CONTRACT.md)。`controller-server/app/agent.py` 提供可运行的 Python CLI Agent，支持凭据保存/恢复、心跳、assignment 轮询和内置 `lastcore/linear-demo-v1` 分片计算；`python -m app.demo` 在本机启动 Controller 与三个 Agent，验证结果汇总。该 Agent 尚不支持预训练模型、节点间 tensor 传输、运行中的取消中断、原生桌面 UI 或 Android 生命周期管理。

- **Controller API**：复用 `controller-server/` 中现有注册、心跳、assignment 查询和状态回报接口。客户端开发前先冻结请求/响应 schema、错误码、认证和版本兼容策略。
- **Agent Core**：负责配置、凭据接口、心跳、轮询、去重、deadline、取消、状态机和结构化日志；不依赖桌面 UI。
- **Executor**：定义稳定的本地执行器接口。先提供可重复的小型 fake executor 做协议联调，再接入真实推理引擎；不要用 fake 结果宣称模型推理完成。
- **Desktop Host**：macOS/Windows 启停、系统托盘或菜单栏、开机启动选项、升级和退出清理。后台常驻必须由用户显式开启。
- **Android Host**：原生 Android 生命周期与前台服务、通知、运行时权限、温控/电量策略；任务执行和网络请求不放在 Activity 生命周期内。
- **管理界面**：首版先提供清晰的节点连接与状态界面。界面框架在确认是否需要统一桌面 UI 后再选型。

## 分阶段任务

- [x] 建立 Controller API contract 文档，记录当前接口字段、认证方式、分页/轮询行为、错误响应和版本策略。参见 [`API_CONTRACT.md`](API_CONTRACT.md)。
- [ ] 定义 assignment 的执行类型、模型标识/版本、资源预算、deadline、取消语义、输入输出引用和幂等键。
- [ ] 明确节点间数据通道：可达地址、TLS/证书策略、连接建立方、端口配置、断连超时与重试上限。
